## 三、已核查、确认无问题（避免重复投入）

* **帧同步**：`index` 每次严格前进（接受帧 `+frameLen`、拒绝帧 `+1`），不漏扫、不重复计数；有效帧载荷内的 `AA55` 因跳帧而不会被误判；假阳性需 4 字节同时命中（≈2⁻³²）。
* **字段解析**：大端拼装、`qint16` 补码、`÷scale` 与 `tools/reference_parse.py` 逐帧一致；偏移在 `isValid` 中限定，读取不会越出帧体。
* **惯导修正**：`mechAxis` 越界被 `continue` 拦截；修正源使用**未修正的原始惯导值**（无累积误差）；6 个修正字段与 X/Y/Z 默认映射正确。
* **无 O(n²)**：`DataSet::appendFrame` 的 `resize` 走 Qt 几何增长，均摊 O(1)；解析主循环线性。
* **QSaveFile 用法**：open 失败报错、写失败 `cancelWriting`、成功 `commit`，正确。
* **生命周期**：`m_manager` 声明在 `m_plot` 之前，Qt 先销毁子控件再析构成员，`DataSet*` 不会悬垂；`m_data = data` 为 `QVector` 隐式共享（无大拷贝）；`QCPItemTracer` 归 plot 所有（QObject 子对象），`clearGraphs` 后 `updatePosition()` 有 `hasPlottable` 守卫。
* **信号环**：`visibilityChanged ↔ setCheckedSilently` 因状态短路 + `QSignalBlocker` 不会递归。
* **QSettings**：数组键名对称、`begin/endArray` 成对、显式传 org/app。

### 4.2 绘图侧：窗口化抽稀加载（本次已实现）

**问题**：原先 `refreshGraphs` 把**全部帧**灌进 QCustomPlot（每点 `key+value` 共 16 字节 ×
19 条曲线），80 万帧时绘图侧独占约 **243 MB**；`setAdaptiveSampling` 只降低绘制开销、不减内存。

**实现**（`PlotWidget::refreshGraphs`）：
1. 只装载「当前可视窗口 ±25% 余量」的数据；
2. 超出 `DisplayConfig::maxPointsPerCurve`（默认 20000，设置界面可改）时按
   `step = ceil(窗口帧数 / 上限)` 抽稀，并强制包含窗口右端点；
3. 已装载窗口覆盖当前视野且步长足够细时直接跳过；
4. 滚轮/平移/框选通过 60 ms 去抖定时器触发重载，拖动过程不频繁重取；
5. 悬停吸附点改为**按 DataSet 精确坐标定位**（不再绑定 graph），因此抽稀不会造成
   “提示数值与吸附点不一致”；悬停数值、CSV、Y 轴自适应统计始终取自 DataSet。

**实测（合成数据，Release + offscreen）**

| 帧数 | DataSet | 全览每曲线点数 | 绘图内存 | 放大到 2000 帧窗口 |
|---|---|---|---|---|
| 1 万 | 2.9 MB | 10 000 | 2.9 MB | 10 000 点 / 2.90 MB |
| 10 万 | 29 MB | 20 001 | 5.8 MB | 2 501 点 / 0.73 MB（步长 1） |
| 80 万 | 232 MB | 20 001 | **5.8 MB**（原 243 MB） | 2 501 点 / 0.73 MB（步长 1） |

→ 绘图侧内存**下降约 42 倍**且与文件大小无关（100MB 上限时同样约 6 MB），
放大后仍是逐帧全分辨率。剩余内存集中在 DataSet（原始值+修正值两份）。

**后续可选优化**：DataSet 只存原始值、修正值按需计算（内存再减半）。

## 八、第三轮：交互缺陷（滚轮缩放导致视图失控）与报告复核

### 8.1 用户报告的现象与定位

**现象**：“缩小以后再放大就恢复不回去了”——曲线被压成平线，滚轮怎么滚都回不到正常视图。

**复现**（用真实控件 + 633 帧实测数据驱动滚轮事件）：

```
初始全览       X=[-0.5, 632.5] span=633   Y=[18.77, 73.51]
放大10格       X span=124.6               Y=[40.75, 51.53]
再放大10格     X span=24.5                Y=[45.08, 47.20]
缩小10格       X span=124.6               Y=[40.75, 51.53]
再缩小10格     X span=633（X 已被夹回全览） Y=[18.77, 73.51]
继续缩小20格   X 不变（已到全局）          Y=[-659.96, 752.24]      ← Y 开始失控
右边缘缩小20格 X 不变                     Y=[-18171, 18263]
中心缩小60格   X 不变                     Y=[-2387315, 2387408]    ← 放大 100 万倍
再放大3格      X 部分恢复                 Y 仍有 ±1.47e6 → 曲线仍是平线
```

**根因**：滚轮使用 QCustomPlot 默认行为**同时缩放 X/Y**；X 轴被 `limitXRange()` 夹在
`[1, 帧数]` 之后不再变化，而 **Y 轴没有任何边界**——每次“缩小”把 Y 跨度乘 1.176，
于是连续几次缩小就把 Y 拉到 ±2.4e6，曲线被压成平线；此后只能按 0.85 倍逐步缩回，
用户滚几下根本回不去。同类问题也存在于右键平移（可把曲线整体拖出视野）。

### 8.2 修复

| 修改 | 说明 |
|---|---|
| 滚轮只缩放帧序号轴 | 构造函数中 `axisRect()->setRangeZoom(Qt::Horizontal)`；Y 由自适应管理，彻底消除“Y 被无限放大”的路径 |
| 滚轮后 Y 自适应 | `wheelEvent` 中调用 `fitYToVisible()`（`getValueRange` 限定在当前 X 窗口内，故结果精确），放大到局部时曲线自动铺满视图 |
| `limitXRange()` 保持中心 | 夹取跨度时以**视野中心**为基准（原来固定 `lower`），消除到达最小跨度后继续滚轮导致的视野漂移 |
| 新增 `limitYRange()` | 右键平移后限制 Y 范围始终与数据范围有交集，避免把曲线拖出视野 |
| `clearSource()` 重置装载状态 | 一并清空 `m_loadedStep/m_loadedKeyRange/m_loadedRaw/m_dataYRangeValid` |

**修复后同一序列**（X 可正常缩回、Y 始终有界并随窗口自适应）：

```
初始全览       X=[-0.5,632.5] span=633  Y=[18.77, 73.51]
放大10格       X span=124.6             Y=[20.79, 73.41]
再放大10格     X span=24.5              Y=[29.98, 72.73]   ← Y 跟随可见窗口
缩小10格       X span=124.6             Y=[20.79, 73.41]
再缩小10格     X span=633               Y=[18.77, 73.51]
继续缩小20格   X span=633               Y=[18.77, 73.51]   ← 不再失控
缩小60格/放大30格交替后仍全部有界
```

**新增回归测试 `wheelZoomKeepsAxesBounded`**：放大 10 格（X 变窄、Y 不超全局）→ 缩小 10 格
（X 回到 -0.5~帧末）→ 再缩小 50 格（X 保持全局、Y 仍有界且覆盖数据范围）→ 交替 5 轮后仍
有界；最后 `resetView()` 能精确恢复初始 Y 范围。
