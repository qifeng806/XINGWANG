# 星网转台数据解析与可视化软件

离线解析转台控制单元串口输出的**定长 hex 数据帧**，完成 25 个物理量的解析、惯导修正与
同坐标系叠加可视化，支撑转台性能测试、误差分析与算法调优。

* 技术栈：**Qt 6.11.0（Qt Widgets）+ QMake + QCustomPlot 2.1.1**，C++17，MinGW 64bit
* 目标平台：Windows 10 / 11 64 位
* 当前协议：**54 字节 / 25 字段（IMU5136 + LINS358 双惯导）**，同时兼容 42 字节旧帧
* 当前版本：v1.0.0

## 二、构建与运行

前置：Qt 6.11.0（Widgets + Print Support + MinGW 11.2/13.1 64bit）已安装。

```bat
:: 1) 打开 “Qt 6.11.0 (MinGW 64-bit)” 命令行，或先把 Qt/MinGW 加入 PATH
set PATH=D:\Qt\6.11.0\mingw_64\bin;D:\Qt\Tools\mingw1310_64\bin;%PATH%

:: 2) 构建主程序（影子构建，产物在 <构建目录>\bin\release）
mkdir build && cd build
qmake ..\XingWang.pro -spec win32-g++ "CONFIG+=release"
mingw32-make -j8

:: 3) 运行（可带数据文件参数）
bin\release\XingWangTurntable.exe ..\sample\20261010_54byte_3841frames.txt
```

Qt Creator：直接打开 `XingWang.pro`，选择 Qt 6.11.0 MinGW 64-bit 套件，构建运行即可；
产物位于 Qt Creator 当前构建目录下的 `bin\release`（或 `bin\debug`）。

> **构建目录约定（重要）**
> `XingWang.pro` 用 `$$OUT_PWD` 指定输出目录，**每个影子构建目录各自拥有 `bin/release`、
> `bin/debug` 与目标文件**。切勿改回 `$$PWD`（源码目录）绝对路径——那会让 Qt Creator 的
> 构建目录与命令行构建目录共用同一批 `.o`，一方「清理项目」后另一方就会报
> `ld: cannot find obj/release/xxx.o`。

> **MinGW 必需编译参数（工程已配置好，勿删）**
> `qcustomplot.cpp` 是约 130 万字符的 amalgamation 单文件，Debug 模式会生成 3 万多个节区，
> 触发 GNU as 报错 `too many sections / file too big`；同时 cc1plus 也可能 `out of memory`。
> 因此 `XingWang.pro` 中固定加入：
> ```qmake
> QMAKE_CXXFLAGS += -Wa,-mbig-obj                       # 必须：COFF 大对象格式
> CONFIG(debug, debug|release) {
>     QMAKE_CXXFLAGS_DEBUG += -fno-var-tracking -fno-var-tracking-assignments  # 降低内存占用
> }
> ```

发布打包：

```bat
windeployqt --release --no-translations build\bin\release\XingWangTurntable.exe
```

单元测试（解析核心，QCoreApplication，无需 GUI 环境）：

`sample/20260923_42byte_1304frames.txt`（42 字节旧帧）；可用环境变量

### 第三方库本地补丁

`thirdparty/qcustomplot/qcustomplot.cpp` 顶部加入了一段带版本判断的兼容补丁：
`QDateTime::toTimeSpec()`、`QDate::startOfDay(Qt::TimeSpec)`、`QImage::mirrored(bool,bool)`
在 Qt 6.9/6.13 起被弃用，补丁在 `QT_VERSION >= 6.9.0` 时改用
`toTimeZone()` / `startOfDay(QTimeZone)` / `flipped(Qt::Orientations)`，
Qt 5.x 与 Qt 6.0~6.8 仍走原路径，行为完全一致，编译告警清零。

## 三、帧协议

当前标准为 **54 字节定长帧（大端序）**，帧内依次包含机械量、IMU5136、LINS358 与信标功率。
解析器会逐帧自动识别 54 字节新帧与 42 字节旧帧，**两者可在同一文件中混合出现**。

### 3.1 54 字节标准帧（25 字段）

| 新帧偏移 | 旧帧偏移 | 长度 | 内容 | 类型 | 换算 | 惯导修正 |
|---|---|---|---|---|---|---|
| 0 | 0 | 1 | 帧头 1 = 0xAA | — | — | — |
| 1 | 1 | 1 | 帧头 2 = 0x55 | — | — | — |
| 2~3 | 2~3 | 2 | 方位目标角度 | uint16 | ÷100 ° | +惯导角度（默认 X） |
| 4~5 | 4~5 | 2 | 方位编码器角度 | uint16 | ÷100 ° | 不修正 |
| 6~7 | 6~7 | 2 | 方位运行速度 | int16 | ÷100 °/s | 不修正 |
| 8~9 | 8~9 | 2 | 方位前馈速度 | int16 | ÷100 °/s | +惯导速度（默认 X） |
| 10~11 | 10~11 | 2 | 俯仰目标角度 | uint16 | ÷100 ° | +惯导角度（默认 Y） |
| 12~13 | 12~13 | 2 | 俯仰编码器角度 | uint16 | ÷100 ° | 不修正 |
| 14~15 | 14~15 | 2 | 俯仰运行速度 | int16 | ÷100 °/s | 不修正 |
| 16~17 | 16~17 | 2 | 俯仰前馈速度 | int16 | ÷100 °/s | +惯导速度（默认 Y） |

| 20~21 | 20~21 | 2 | 横滚编码器角度 | uint16 | ÷100 ° | 不修正，显示环绕 ±180 |
| 22~23 | 22~23 | 2 | 横滚运行速度 | int16 | ÷100 °/s | 不修正 |
| 24~25 | 24~25 | 2 | 横滚前馈速度 | int16 | ÷100 °/s | +惯导速度（默认 Z） |
| 26~27 | 26~27 | 2 | IMU5136 角度 X | int16 | ÷100 ° | 修正源 |
| 28~29 | 28~29 | 2 | IMU5136 角度 Y | int16 | ÷100 ° | 修正源 |
| 30~31 | 30~31 | 2 | IMU5136 角度 Z | int16 | ÷100 ° | 修正源 |
| 32~33 | 32~33 | 2 | IMU5136 速度 X | int16 | ÷100 °/s | 修正源 |

| 50~51 | **38~39** | 2 | 信标功率值 | int16 | ÷100 dBm | 不修正 |

| 53 | 41 | 1 | 帧尾 2 = 0xAA | — | — | — |

> 旧帧（42 字节）只到 IMU5136 速度 Z 为止，没有 LINS358；信标功率位于 38~39、帧尾位于
> 40~41。LINS358 字段在旧帧中解析为 0，界面仍保留这 6 条曲线（数值为 0）。

### 3.2 惯导修正来源

设置 → 帧协议中提供“修正来源”三选一，默认 **仅 IMU5136**（与加入 LINS358 之前的旧版行为一致）：

| 修正来源 | 修正公式 | 旧帧行为 |
|---|---|---|
| IMU5136（默认） | 修正值 = 机械量 + IMU5136 对应轴 | 正常 |
| LINS358 | 修正值 = 机械量 + LINS358 对应轴 | 无 LINS358，自动回退为 IMU5136 |
| 两者 | 修正值 = 机械量 + IMU5136 + LINS358 | 仅叠加 IMU5136 |

只有 6 个字段参与修正：

```
目标角度（方位/俯仰/横滚） = 原始目标角度 + 对应轴惯导角度
前馈速度（方位/俯仰/横滚） = 原始前馈速度 + 对应轴惯导速度
```

另有惯导修正总开关、三轴独立开关与“机械轴 → 惯导轴”映射（默认 X/Y/Z）。
修正始终使用**未修正的原始惯导值**，不存在累积误差。

### 3.3 字段与配置持久化

* 25 个字段（含 IMU5136、LINS358 两套）始终保留在字段表中，不因修正来源而隐藏。
* 设置的 schema 版本为 v2，完整保存字段名称、单位、类型、换算系数、环绕方式、
  新帧偏移、旧帧偏移、修正来源、机械轴、分组与颜色。
* 旧版配置（42 字节 / 19 字段 / 无版本号）会自动迁移：帧长 42→54、补入 LINS358 六字段、
  信标旧帧偏移保持 38，用户其它配置不丢失。

| 右键平移 | 绘图区按住**右键**拖动整体平移（Y 轴受限于数据范围，不会把曲线拖出视野） |

异常容错：文件不存在或无权限、空文件、非法 hex 字符、无有效帧、错误帧占比 > 10%、
文件尾部残帧等均有明确提示与统计，不会崩溃。残帧口径为**最后一个已接受帧之后的全部字节**，
与 Python 参考实现一致。

### 性能与内存

* 解析为单遍线性扫描，帧同步失败仅前进 1 字节，不会漏帧。
* DataSet 按“帧 × 25 字段 × 原始与修正两份 double”连续存储，约 **400 字节/帧**。
  100MB 源文本（过滤后约 50MB hex）约 92 万帧，常驻约 **370MB**；QVector 扩容期间
  峰值会更高（约 1.5 倍）。这是当前业务数据规模下接受的代价，未做有损压缩。
* 绘图侧采用**窗口化装载**：只保留当前可视窗口 ±25% 余量的数据，超过
  `DisplayConfig::maxPointsPerCurve`（默认 20000）时按桶做 **min/max 包络抽稀**，
  每桶保留最小值和最大值两个点，因此全览时尖峰不会被抹掉；放大后桶宽变为 1，
  自动恢复逐帧全分辨率。绘图内存上限与文件大小无关：
  25 条曲线 × 20000 点 × 16 字节 ≈ **7.6MB**。
* 拖动/缩放通过 60ms 去抖触发窗口重载；窗口已覆盖当前视野且桶宽足够细时直接跳过。
